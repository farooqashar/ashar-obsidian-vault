### Two real bugs, caught by the script's own guard rather than by luck

The tagger refuses to write unless the rewrite differs from the original by exactly the number of lines it meant to add. On the first live run that guard fired on all 12 notes and wrote nothing. Both causes were real:

1. **Notes do not end with a newline.** Web Clipper output has no final `\n`, so `wc -l` undercounts every note in this vault by one, and the guard's arithmetic was off by one everywhere. Now computed with `awk 'END{print NR}'`, which counts a final unterminated line. The fix also preserves the missing EOF newline instead of silently appending one — otherwise every tagged note would have gained a byte and shown up as modified in git for no reason.
2. **`author:` is a YAML list too.** `Runtime Promises` has `author:` / `  - "[[Denys Zhak]]"`, and the already-tagged check was counting any dash-line in the frontmatter, so that note looked already-tagged and was skipped. The check now only counts dash-lines inside the `tags:` block. This is the third variant of the bug the 2026-09-29 and 2026-11-03 notes warn about: first the opening `---` parsed as a tag, then the missing newline before the closing `---`, now a different list-valued key entirely. The lesson is narrower than "handle the delimiters" — frontmatter dash-lines mean nothing until you know which key they belong to.

A third bug never reached the vault: the duplicate-retirement block had `AI-Agents/Braindate.md` and `AI-Agents/TinyFish.md`, names from an older report. Both notes have since been renamed and Braindate moved folders. The duplicate scan is what surfaced the real paths; they are corrected in the script. Retirement is off by default, so it would have printed `SKIP retire, keeper missing` rather than doing damage — but it would have done nothing while looking like it had. **Standing note for future runs: build the retire list from that run's own scan, never from a previous report's filenames.**
